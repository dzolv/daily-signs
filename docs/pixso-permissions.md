# Pixso 首次接入与最小权限

先让她照常选图。第一次接入时，模型只简短说明需要本人登录授权、指定工作画板，并在测试副本验证；不要默认让她开启整机 bypass，也不要把安装说明整页念给她。

## 模型第一次怎么提醒

模型先执行 `npm run setup -- status`，或读取交接命令返回的 `setup`。`needsReminder: true` 时可以说：

> 第一次需要你登录自己的 Pixso 并授权连接。你指定日签画板后，我先确认能读，再在测试副本试一下修改和导出。文件保存在本项目里；如果权限不足，我会告诉你具体缺哪一项，不用先把整台电脑的权限都打开。

实际说明后，模型记录已经说过的文本：

```powershell
npm run setup -- acknowledge --message "已说明本人登录授权、指定日签画板、先在测试副本验证修改和导出；不默认要求整机 bypass。"
```

这只是避免反复介绍的本地记录，不是用户授权，也不是连接或权限检查成功。不要在尚未说明时预先记录。记录不提交，换电脑/新克隆会重新提醒；说明版本变化时也会提醒。换账号、换目标、扩大工具范围时，即使曾介绍过，仍要按当前任务说明新增需要的访问。正常使用不重复打断选图。

## 真正的许可：提出范围、询问、记录、核对

首次说明和用户许可分开保存。模型先整理具体请求，再向用户用一两句话询问，例如：

> 可以读取你这个 Pixso 文件中的“本期选图”区域，并在测试副本替换文案、图片和导出吗？读取的内容会由当前模型服务和 Pixso 处理，图片与成品保存在这个项目的本地目录。我只会为这批工作开放所需设计工具。你也可以先只允许读取。

实际问题必须替换成可识别的文件/区域、要改的内容、所需工具权限以及本地位置。只申请当前任务需要的范围，不因本地程序只有一个使用者就省略询问。授权目标不明确时先问，不能为准备许可扫描整个账号。无需让她填写表格或 JSON，模型根据现有页面与会话准备输入。

已有会话明确授权同一范围，可以保存真实依据，不再问一次。“看一下这张画板”不等于允许修改；“完成这批日签”可以覆盖已说明的制作步骤，但不能推导出支付、发布、删除或整机权限。OAuth 授权页和宿主要求的最终确认仍由实际客户端流程处理，CLI 的许可记录不能替代。

模型使用 `npm run consent -- --help` 查看命令：

1. `propose --input .local/...json` 保存范围为待确认，并返回可供询问的摘要；这一步不批准任何动作。
2. 用户明确回答后，`decide ID --revision N --decision approved|denied --evidence "实际答复及会话出处"` 记录决定。允许范围变小应建立新的请求，不把部分同意录成全部同意。
3. 每次远端步骤/新执行者开工前，`check ID --input .local/...json` 核对本次要使用的范围。仅同账号、同文件且各项属于已同意范围才可覆盖；待确认、拒绝、撤回或新增范围不能获得执行配置。
4. 用户撤回后，先停止新的远端操作，再用 `decide ... --decision revoked` 保存撤回。已开始的外部调用无法靠本地记录取消，须读取实际结果并告知，不擅自补偿删除。

记录以账号标签、文件、节点列表、操作、工具和本地路径标明范围；账号标签只用于区分，不能冒充已验证的登录身份。范围比较使用明确成员，不推导节点后代或目录前缀权限。不要使用 `*` 表达整个账号。私有输入、答复依据和许可 ID 留在 `.local/`；把许可 ID 关联到当前批次的交接进度，接手模型再次检查，不继承旧进程“工具已批准”的假设。

程序的 `check` 通过后会给出本次工具允许名单、默认需审批、逐工具批准以及本地只读/项目写入的配置建议。模型应核实人类许可和当前宿主规则后，才将建议用于单次启动；不自动修改全局配置。`scopeCovered` 只是本地记录的范围覆盖检查，不是独立人类身份认证，也不拦截绕过 CLI 的直接 MCP 调用。拒绝/损坏/过期版本应停止，不得改文件伪造通过。

以下是供模型生成私有输入时参考的合成示例，实际 ID 只保存在 `.local/`。七个字段必填，列表可按需为空；远端操作必须有明确节点和工具，本地写入必须有具体路径。用途变化也会要求新请求。

```json
{
  "accountRef": "synthetic-account-label",
  "documentRef": "synthetic-test-file",
  "nodeRefs": ["synthetic-test-frame"],
  "actions": ["read", "export", "local-write"],
  "tools": ["query_nodes", "get_export_image"],
  "localPaths": [".local/export-raw/synthetic.png", ".local/export/synthetic.png"],
  "purpose": "读取并导出已约定的本批测试画板"
}
```

相同用途下请求范围可为已许可列表的子集，不能增加新成员。操作标签不会约束远端工具内部能力：例如带脚本能力的工具即便标记在一次读取任务里也仍然能写，模型必须核对工具真实功能再申请。程序返回的 `ok: true` 只表示检查命令完成；执行必须看 `scopeCovered: true`，检查未覆盖时进程退出码为 1。

当前尚未提供自动启动/拦截所有模型执行的调度器。模型需要遵守上述检查流程；未来若增加调度器，必须在发出远端调用前强制执行范围核对，而不是仅把许可文本放进提示词。

## 权限分成三层

| 层级 | 最小起点 | 什么时候增加 |
| --- | --- | --- |
| 本地命令 | 纯读取诊断用 `read-only`；压缩和交接用项目范围 `workspace-write` | 素材下载需要命令联网时，单独处理实际来源；安装/更新依赖放在维护会话 |
| Pixso 工具 | 只暴露当前步骤需要的工具，逐工具决定审批 | 编辑、创建或导出之前按实际工具能力扩展，保留不需要的工具为禁用/不可见 |
| Pixso 账号与文件 | 本人 OAuth、指定文件查看权限 | 制作需要目标文件编辑权限；席位或功能限制以服务返回为准 |

`workspace-write` 限制本地命令写入范围，不等于禁止 MCP。`read-only` 也不意味着远程设计只读：远程写入另由 MCP 工具和账号权限控制。命令联网开关不负责 MCP 服务连接、模型请求或浏览器网络。不要用一个“权限已开”概括这几层。

`approval_policy=never` 表示不能弹审批，**不是批准所有操作**。工具默认要求审批时，非交互 CLI 会直接返回 `MCP tool call requires approval, but approval policy is never`。这不是 Pixso 的会员报错。

## 已验证的窄范围读取

2026-11-04，Codex CLI `0.166.0-alpha.5.1`、6.1 Terra：保留本地 `read-only`、不开放命令网络、仅暴露并批准 `get_top_level_frames`，真实读到了测试日签画板。说明无需先使用 bypass。机器和客户端版本变化后应复验。

随后仅开放 `query_nodes`、`replace_props`、`get_export_image`，实测签名节点字号 13 → 14 → 13，逐次读回核实，文字不变；2x PNG 导出调用返回成功。导出 Base64 在工具输出中被截断，本轮没有验证这份 MCP 导出的完整文件；此前网页导出的 PNG 已完整解码与压缩验证。修改文字、替换背景、创建图层和更多工具尚不在这组权限验收范围内。本次账号的网页显示免费版，但不能由这组成功调用保证所有免费账号或所有 MCP 功能可用。

2026-11-06，当前聊天直接加载 Pixso MCP 后，再次读取了测试画板及签名，并把 `get_export_image` 的完整返回值留在工具执行环境中，避免将 Base64 展开到模型上下文。完整 PNG 保存后成功解码：1200×1600，原始 147,272 字节，压缩后 41,807 字节。因此完整 MCP 导出这一缺口在本机已补齐。其他宿主应提供等价的完整结果保存能力，不让模型手抄被截断的 Base64。

以下是供模型参考的**单次启动参数**，不会写入全局配置。工具名以实际服务清单为准。提示中的目标引用由模型从用户指定页面或私有交接记录取得，不写入公共文件。

```powershell
codex exec --ephemeral --sandbox read-only --model gpt-6.1-terra `
  -c 'mcp_servers.pixso.enabled_tools=["get_top_level_frames"]' `
  -c 'mcp_servers.pixso.default_tools_approval_mode="prompt"' `
  -c 'mcp_servers.pixso.tools.get_top_level_frames.approval_mode="approve"' `
  "只读取本次明确指定的测试文件，返回真实调用结果；不要调用其他服务或修改文件。"
```

工具允许名单限制暴露哪些 Pixso 工具；`approve` 是客户端预批准，应用前应确保当前任务已授权。默认按工具申请；用户明确选择信任 Pixso 时，可以在本次执行中为 Pixso 设置服务器级信任。其余工具保留宿主自动审批，不关闭无关服务器/插件，也不另加一套人工审批。不得覆盖管理员要求或为被拒动作自动扩大权限。

本项目用户已选择“Pixso 信任，其余交给自动审批”的执行方式。CLI 可使用 `codex exec --approve-for-me -c 'mcp_servers.pixso.default_tools_approval_mode="approve"' --model gpt-6.1-terra`，并附上当前已授权任务。参数只影响本次执行，不修改全局配置。服务器级信任并不限定文件，因此仍按用户指定的目标工作；新账号或无关文件不能从这次信任推导出许可。首次使用者仍需本人完成 OAuth，并确认自己的制作范围。

工具白名单也**不限定文件或节点**：这些工具参数仍能指向账号有权限的其他文件。指定目标的提示是执行约束，不是强制访问控制。需要真正文件隔离时，用 Pixso 自身的共享权限或专用工作空间限制账号可见范围。

## 制作时按步骤开放

先发现实际参数，不能只凭工具名猜功能。此次检查发现 `replace_props` 可改字号/样式，却不能直接替换文字内容。

- 检查图层：按需用 `query_nodes` 或 `get_node_dsl`；已有稳定节点时不必每次列整个文件。
- 看构图：按需用 `take_screenshot`。
- 样式调整：只有确实支持指定属性且能限于目标节点时使用 `replace_props`。
- 导出：`get_export_image`，核对指定目标与原尺寸 1x PNG 设置（用户另有要求时按要求），将完整返回交给 `workflow save-export` 保存到 `.local/export-raw/`。本地显式清单批压/恢复用 workflow，远端设计操作仍由模型使用现有 Pixso 工具承担。
- 创建图层、替换文案或背景：先查 `apply_design` 等实际能力，再开放确需工具。通用 `eval_script` 执行面较大，不作为首次连接的默认授权。

交互使用可以保留工具的 `prompt`/`writes` 审批，在客户端确认具体动作；非交互执行需要事先明确当前批次授权，并仅为所需工具配置审批。若工具的破坏性标记、组织策略或客户端仍要求审批，应停止并说明，回到可审批的会话处理；不保证单工具预批准能覆盖所有限制。

日常制作的本地权限可以从 `workspace-write` 起步，保留代码和依赖，工作数据只写 `.local/`。更细的“项目只读、仅 `.local/` 可写”可用 Codex beta permission profiles；本机 Windows 使用 legacy `unelevated`，官方说明它不能执行所有读写分区规则，因此未把这套未验证配置自动安装给用户。`workspace-write` 也不代表整机其他文件完全不可读。

## 首次验收与故障定位

1. 本人完成官方 OAuth。不要复制密码/token 给模型，不重复使用已结束的回调页面。网页登录与 MCP 授权分别核对。
2. 新会话确认工具实际加载，向指定测试文件发起只读调用。配置存在、工具可见均不足以证明读成功。
3. 在已授权测试副本做一次可逆修改并读回；恢复原值并再次核实。失败时先查远端状态，不重复创建内容。
4. 导出一张原尺寸 1x PNG，完整保存后按显式清单压缩，检查真实尺寸和大小。视觉快速确认文字可读、无明显漏字；记录已验证范围，不能从读取成功推导全部工具可用。
5. 保存目标和真实观察到私有交接记录。新执行会话仍要检查工具及目标，不继承上一个聊天的审批状态假设。

| 观察到的结果 | 处理 |
| --- | --- |
| 工具不存在/未加载 | 检查当前客户端连接、重启服务或新执行会话；不要求重买会员 |
| OAuth 未登录/认证失效 | 引导本人重新授权，不读凭据文件 |
| 调用前要求审批且策略为 never | 检查实际工具审批配置，按当前已授权步骤做窄范围处理 |
| 服务返回无文件权限、席位不足 | 保留真实错误，说明缺少的是文件权限还是产品资格；不自动付费 |
| MCP 暂不可用、网页可编辑 | 可用已授权浏览器路径继续，但注明未验证 MCP，不能伪造结果 |
